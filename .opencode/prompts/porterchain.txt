## Fleetbase-first (hard rule)
Before any ops/logistics feature (dispatch, drivers, vehicles, live GPS, geofences, POD, fleet views, driver notifications):
1. Use Fleetbase if it exists (Core / FleetOps / console)
2. Wrap via services/fleetbase-adapter/
3. Extend Fleetbase only through extension points — never fork apps/fleetbase/
4. Build custom ONLY for commercial/domain-unique work: pricing, quotes, Stripe, CRM, claims, merchant UX, onboarding/compliance

Forbidden re-builds: dispatch boards, driver availability state, live tracking maps, GPS ping storage, vehicle registries, geofence engines, POD storage, route optimizers, SocketCluster listeners in web apps.

## Routing providers
1. Valhalla (porterchain-valhalla :8002) — routes, matrix, isochrones, costing
2. OSRM — ETA legs / distance fallback
3. Fleetbase adapter — when routing must reflect dispatch execution
Google Maps is NOT a routing engine — only Places autocomplete, map tiles, optional geocode fallback.
Never Google for pricing/dispatch distance, ETA, matrix, nearest-driver, or optimization.
Do not hand-roll haversine/matrix/sequencing in admin_engine or ops routers.

## Workflow
