**Hard rules for closing gaps**

1. **Do not delete or replace** existing PorterChain website content. **Add** missing pages, sections, and depth.
2. Getcho is **software-only** (orchestration SaaS + multi-fleet). PorterChain is **full-stack**: proprietary software **+ drivers + vehicles + operations + compliance**.
3. Adapt Getcho _content patterns_ **and professional site structure / presentation** (hubs, verticals, feature deep-dives, guides, case studies, FAQ density, EEAT, page templates). Do **not** copy US geography, Shopify-first ICP, “Book a demo,” SaaS pricing tiers, or **any Getcho brand name onto porterchain.com**.
4. Primary CTA remains **Get a quote / request capacity** → Clerk → customer portal.
5. Geography: **GTA / Ontario** first. SEO/GEO expansions stay local-true.
6. Match or exceed Getcho’s **professional presentation bar** while keeping PorterChain’s full-stack story (see §1b and [PORTERCHAIN_FULL_STACK_CONTEXT.md](./PORTERCHAIN_FULL_STACK_CONTEXT.md) §15b).

## 1b. Professional structure & presentation (observe → apply to PorterChain)

Getcho’s public site is a useful **structure and craft** benchmark — not a business-model template. PorterChain should adopt the _professional pattern_, rewritten for capacity + tech + ops.

### What Getcho does well (structure / UX craft)

| Pattern                                 | How it shows up                                                                                        | PorterChain application                                                                              |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------- |
| **Hub → spoke IA**                      | `/features`, `/integrations`, `/guides`, `/delivery-for/*`, `/services/*` each have index + deep pages | Add capability hub + deep landers; keep `/business`, `/solutions`, `/vehicles` as hubs               |
| **Mega capability page**                | `/features/` — at-a-glance table, then narrative sections, then FAQ                                    | Build `/capabilities` or expand `/platform` with the same density (digital **and** physical columns) |
| **Categorized integration grid**        | E-comm / comms / ops / WMS / ERP / custom                                                              | Upgrade `/integrations` to the same card taxonomy + detail pages                                     |
| **Vertical playbook pages**             | `/delivery-for/{niche}`: hero → benefits → proof → FAQ → related                                       | Deepen `/solutions/*` and industry niches to this length                                             |
| **Capability landers**                  | `/services/{capability}`: outcome hero → how it works → FAQ → related                                  | Add PorterChain capability URLs (multi-stop, recurring, tracking, recovery, AI ops)                  |
| **Long-form guides**                    | 10–15 min guides with TOC-like H2s and implementation steps                                            | Restore/publish indexable `/guides/*` at that depth (GTA capacity framing)                           |
| **Repeated proof modules**              | Ops-impact bands / testimonials                                                                        | Add reusable proof bands (only with real EEAT evidence)                                              |
| **Related-content block on every page** | Integrations + services + stories links                                                                | Standardize “Related” blocks sitewide                                                                |
| **FAQ with full answers + schema**      | JSON-LD FAQPage on hubs and landers                                                                    | Ensure every hub/lander has complete answers (not questions-only)                                    |
| **Clear primary CTA cadence**           | CTA in nav, hero, mid, end                                                                             | Same cadence with **Get a quote** / specialist — never demo                                          |
| **Scannable presentation**              | Short subheads, cards, tables, product UI mock sequences                                               | Keep PC visual system; add operational UI + fleet visuals that show full-stack                       |
| **Nav / footer completeness**           | Product, industries, integrations, guides, company always reachable                                    | Audit footer/nav so new pages are linked (SEO + professionalism)                                     |

### Page template PorterChain should standardize (add-only)

```
Hero (outcome + CTA)
→ Proof / trust strip
→ How it works OR capability grid (tech + drivers/vehicles)
→ Detail sections (one job each)
→ Use cases / industries / when to call us
→ Social proof / case study teaser
→ FAQ (full answers)
→ Related links
→ Final CTA band
```

### Presentation quality bar for PorterChain

- **Enterprise-clean:** consistent type, spacing, section rhythm; no cluttered generic “AI SaaS” clichés
- **Ops-credible:** language for ops managers; show dispatch → driver → vehicle → POD
- **Conversion-obvious:** quote path always visible; secondary = talk to logistics specialist
- **EEAT-visible:** trust links, dates on guides/posts, insurance/compliance where relevant
- **No competitor brands** on any public PorterChain URL

### PorterChain gap vs this bar (today)

| Area                                               | Status                   |
| -------------------------------------------------- | ------------------------ |
| Trust / legal / vehicle SKUs / local SEO scaffolds | Strong                   |
| Capability mega-page + service landers             | Weak vs Getcho           |
| Integration hub card density + detail pages        | Thin                     |
| Guide length & guide index                         | Thin / partly redirected |
| Blog / case-study volume                           | Behind                   |
| Homepage full-stack storytelling + proof modules   | Uneven vs `/business`    |
| Related-link + FAQ completeness on every lander    | Inconsistent             |

**Rule:** When adding pages from this gap list, ship them at **Getcho structural quality**, with **PorterChain full-stack messaging**.
